# 静态潜客池-治理层增强方案-v1

## 摘要

本方案定义静态潜客池下一阶段的 `治理层` 增强方式，目标是在不把系统做重的前提下，保证后续背景字段 enrichment、证据补充和分享派生都不会污染事实源。

## 一、治理目标

本轮治理层只回答三个问题：

1. 新增背景字段如何稳定挂到 canonical account
2. 证据如何结构化支撑背景字段
3. enrichment 如何做到重复执行不脏化

## 二、canonical 与 alias 规则

### 固定规则

1. 任何新增公司先查 `alias_registry`
2. 任何新增背景字段先挂到 canonical account
3. merge 后 evidence / queue / note 引用必须同步修正
4. 边界主体未裁决前，不进入稳定共享层

## 三、evidence 结构增强

### 目标

让背景字段和重点公司说明能回到结构化证据，而不是只靠 note 文本。

### 推荐最小结构

- `account_id`
- `supports_dimension`
- `field_name`
- `field_value`
- `evidence_summary`
- `source_locator`
- `evidence_strength`
- `checked_at`

### supports_dimension 建议

- `identity`
- `background_profile`
- `business_model`
- `digital_signal`
- `event_signal`
- `persona_support`
- `share_support`

## 四、enrichment 幂等规则

### 固定规则

1. 同主体多次补充背景字段，不得新增重复主体
2. 同字段重复补充时，应优先更新事实值或追加证据，而不是复制一整行记录
3. note 中的背景快照若与事实源冲突，以 Excel 为准

## 五、当前边界

本轮治理层不做：

- 动态机会字段治理
- 联系人治理
- CRM 同步治理
- 自动评分系统

## 六、验收标准

1. 新背景字段能稳定挂到 canonical account
2. evidence 能支撑背景字段与重点公司摘要
3. cleanup 时能识别背景字段冲突而不只是主体冲突
4. enrichment 反复执行不会制造第二套事实
