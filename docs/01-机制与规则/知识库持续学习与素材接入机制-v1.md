# 知识库持续学习与素材接入机制 v1

## 1. 目标

本机制用于保证当前潜客池的知识库不是一次性产物，而是一套可以持续学习、持续扩展、持续接入新素材的系统。

它主要解决 3 个问题：

1. 新素材来了，如何稳定进入知识库
2. 新样本上移了，如何帮助发现素材缺口，但不反向决定知识库范围
3. 模型整理过的内容，如何不被误当成知识源本身

## 2. 基本原则

### 2.0 扩展顺序必须固定

后续知识库、画像和潜客池的扩展顺序，应固定为：

1. `原始素材持续学习`
2. `知识库增强`
3. `ICP 画像更丰富 / 更细`
4. `潜客发现能力更强`
5. `潜客池更多元`

也就是：

- 先扩知识，再扩画像，再扩池
- 不允许先用当前潜客池反推知识库主方向
- 不允许先用当前有限样本决定画像扩展主方向

当前潜客池和已有样本，只能帮助我们发现“值得继续学习和观察的方向”，不能替代原始素材池本身成为主驱动。

### 2.1 知识库不是模型产出物堆

知识资产只能建立在真实来源上：

- 真实客户案例
- 官方材料
- 已验证项目经验
- 已校验项目材料
- evidence 中已挂接的一手来源

模型的作用是：

- 提炼
- 分类
- 映射
- 压缩
- 生成可复用表达

以下内容都不是知识学习素材源本身：

- 主表摘要
- 潜客档案页
- 重点公司 note
- 专题包
- 模型生成的总结、映射和话术

它们只能作为导航层、阅读层和线索提示层，不能直接进入学习队列当作素材源。

### 2.2 知识库必须持续扩展，但不能被当前潜客池反向锁死

知识库来源不只是一开始学习过的内部案例，还应持续接收两类增量：

1. `新素材接入`
2. `样本观察触发的素材缺口提醒`

这里必须强调：

- 当前 `L1 / L2 / L3` 样本只能帮助发现“可能还缺哪类原始素材”
- 不能由当前高质量样本反向决定“知识库只学什么”
- 否则会形成“用当前认知筛样本，再用样本反过来限制知识来源”的自收窄循环

### 2.3 不要求所有材料立刻抽成资产

新材料默认先进入学习队列，再决定：

- 直接抽成知识资产
- 暂时保留在原始材料层
- 作为待观察素材

## 7. 两条核心增长路径

### 路径 A：新素材接入

适用场景：

- 团队给新材料
- 用户新提供案例、方案、文章、链接
- 新扫描到值得学习的高质量材料

标准流程：

1. 先进入 `learning_queue`
2. 先判断来源真实性与可用性
3. 再判断属于哪类资产：
   - `customer_case`
   - `solution_playbook`
   - `industry_insight`
   - `sales_narrative`
   - `mapping_fact`
4. 通过后再进入 `knowledge_assets`

### 路径 B：样本观察触发素材缺口提醒

适用场景：

- 新上移到 `L3/L2/L1` 的样本
- 新形成的重点公司解释
- 新完成的一轮主线提纯

标准流程：

1. 判断该样本是否暴露出某类素材缺口
2. 将这类缺口记录为“待补原始素材方向”
3. 再回到原始素材池、团队新增材料、项目材料和官方材料中主动查找
4. 只有找到明确原始材料、官方材料、项目材料或 evidence 已挂接来源后，才生成学习队列项
5. 档案 / evidence / note 只能帮助定位素材方向，不得作为学习队列中的素材源字段
6. 再决定形成：
   - 案例资产
   - 洞察资产
   - 话术资产
   - 映射资产

补充边界：

- 样本观察是“提示器”，不是“定盘星”
- 学习队列的主增量，仍应来自原始材料池的主动扫描与团队新素材接入

## 8. 什么时候必须触发知识回流

以下情况默认必须触发“知识回流检查”，而不是只停留在主表或 note：

1. 新上移到 `L2/L1` 且具有代表性的样本
2. 新重点公司 note 中出现一组稳定可复用解释
3. 新专题包中出现一组稳定共性
4. 新边界问题被反复发现
5. 团队新提供学习素材

这里的“回流”含义是：

- 先触发查找对应原始材料
- 查到真实来源后，才允许写入 `learning_queue`
- 如果只有模型整理结果、没有真实素材，则只能记为“待补原始素材”，不能进入学习队列

这里的目的不是让当前高质量样本来主导知识库边界，而是提醒我们：

- 还有哪些重要素材尚未被学习
- 哪些赛道、场景、打法仍缺一手材料支撑

## 9. 进入正式知识资产的门槛

一条候选素材只有同时满足以下条件，才进入正式知识资产层：

1. 有明确真实来源
2. 能清楚说明适用主线
3. 能清楚说明支撑哪类判断或画像
4. 能说明怎么被调用
5. 不是只依赖模型二次总结
6. `learning_queue.material_path_or_url` 指向的不是档案页、重点公司 note、专题包或其他模型整理结果

## 9.1 学习范围的主决定因素

未来知识库“学什么”，主决定因素应按以下优先级排序：

1. 原始素材池的广度与质量
2. 团队新提供的真实材料
3. 业务主线本身需要覆盖的行业 / 场景 / 方案空白
4. 样本观察暴露出的素材缺口

不应采用以下错误顺序：

1. 先用当前知识和画像找出 `L1 / L2`
2. 再只围绕这些 `L1 / L2` 去决定知识库学什么

因为这样会让知识库越来越窄，只会强化当前已经成立的认知，而不利于发现：

- 尚未充分覆盖但值得进入的行业
- 当前样本还薄的子赛道
- 还没形成稳定画像的新经营复杂度类型

## 10. 与现有能力的关系

### 与潜客档案层

- 档案层回答：这家公司已经知道了什么
- 学习队列回答：这家公司里哪些信息值得反哺成知识资产

### 与 evidence

- evidence 回答：这些信息从哪来
- 学习队列只在来源清楚后，才允许转正

### 与知识资产

- 学习队列是入口层
- 知识资产是转正层

## 11. 对 skill 的要求

### `static-pool-promote`

当出现以下情况时，应自动触发“知识回流检查”：

- 账户新上移到 `L2/L1`
- 且具备明显代表性

此时至少要：

1. 先检查是否已有可用原始材料包、官方材料或 evidence 已挂接的一手来源
2. 若找到了真实素材，再在 `learning_queue` 中新增一条 `promote_backflow`
3. 若没找到真实素材，只记录“待补原始素材”，不得把档案页或 note 直接写进 `learning_queue`

### `static-pool-share`

当专题包或团队分享中反复使用某组解释时，应判断是否需要反向查找原始素材，并进一步生成：

- 案例资产
- 话术资产
- 洞察资产

### 手工接入

团队提供新素材时，不允许直接跳过学习队列进入正式知识资产表。

档案页、重点公司 note、专题包或模型总结本身，不得以“手工接入”名义进入学习队列。

## 12. 当前建议

下一阶段知识库扩充，不建议先横向继续铺很多新洞察，而应优先：

1. 先主动扫描原始素材池里尚未进入资产层的高价值材料
2. 把经营诉求画像补成成套资产
3. 用学习队列承接后续团队给的新素材
4. 再用样本观察去提示“哪些原始材料方向还没学够”

## 13. 一句话收口

未来知识库应按以下顺序持续扩展：

- `先接收新素材，或由新样本定位原始素材`
- `先进入学习队列`
- `再做结构化抽取`
- `最后进入正式知识资产层`

这样才能保证知识库既能持续学习扩展，又不会把模型自己的整理结果误当成知识本身。
