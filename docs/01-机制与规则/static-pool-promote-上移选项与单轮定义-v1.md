# static-pool-promote 上移选项与单轮定义 v1

## 摘要

`static-pool-promote` 不应再被理解为一个“直接上移”的动作，而应被理解为：

1. 先给用户一组清晰的上移选项
2. 用户选定本轮范围
3. 再执行真实的强核验与升层

这样可以避免“上移一轮”在执行时持续模糊。

## 一、为什么要先给用户选项

如果不先给选项，“上移”通常会同时模糊掉这些问题：

- 本轮上移几个？
- 从哪一层开始？
- 是按主线做，还是按画像做？
- 是优先做最稳的，还是做用户点名的？

因此，`promote` 最好的默认行为不是直接开跑，而是：

- 先生成 `本轮上移选项卡`

## 二、默认选项类型

### 1. 按层级选

例如：

- 从 `L4` 挑 `2` 家上移
- 从 `L5` 挑 `2-3` 家做强核验
- 优先处理最接近上移的候选

### 2. 按主线选

例如：

- 零售消费上移一轮
- 跨境电商上移一轮
- 先进制造上移一轮

### 3. 按画像选

例如：

- 多门店连锁零售画像里挑一轮
- 多平台品牌出海画像里挑一轮
- 多工厂制造集团画像里挑一轮

### 4. 按成熟度 / 队列选

例如：

- 挑已有 `promotion_review` 的
- 挑证据最厚但还没上移的
- 挑最接近上移的 `2` 家

### 5. 按用户点名选

例如：

- 只处理森马、绝味、吉宏
- 只处理这几个公司

## 三、默认输出格式

正式执行前，默认先输出三段：

### 1. 推荐上移模式

提供 `1-3` 个清晰可选模式。

### 2. 本轮建议候选

每个候选至少说明：

- 当前层级
- 主线
- 业务形态画像
- 为什么接近上移
- 当前缺口

### 3. 预计上移结果

例如：

- 若补强证据，可从 `L4 -> L3`
- 若仍证据不足，则维持当前层级

## 四、单轮上移的定义

一轮上移不等于“改几条层级字段”，而是：

一小批候选完成以下闭环：

1. 选定对象
2. 补强证据
3. 重判三大判断字段
4. 正式升层
5. 同步更新主表、evidence、queue、共享层与 note

## 五、默认节奏建议

默认建议：

- `1` 轮处理 `1-3` 个对象
- 最推荐的是 `每轮 2 个左右`
- 若对象复杂，可一轮只做 `1` 个

不建议一轮处理过多，否则容易退化成批量改标签。

## 六、边界

本规则只适用于：

- 静态潜客池内部上移

不适用于：

- 动态机会优先级判断
- 成交概率判断
- 联系人推进逻辑
