# 项目运行迁移清单-v1

## 1. 适用范围

本清单用于把当前“静态潜客池执行层”迁移到另一台机器或另一个 coding agent 终端，目标是保证：

1. 可直接运行 `enrich -> promote -> run_execution_batch`
2. 可做主表修复、完整性体检、写回防冲突
3. 可延续潜客档案与知识库补证链路

---

## 2. 迁移模式（先选一种）

### 2.1 模式 A：全量迁移（保留历史档案）

适用场景：

1. 你确认现有潜客档案 Markdown 质量可接受
2. 你希望在新环境保持历史阅读连续性

### 2.2 模式 B：Clean Start（推荐）

适用场景：

1. 现存潜客档案 Markdown 污染或写坏较多
2. 你希望在新环境只重建高质量档案

策略：

1. 迁移事实与治理底座（工作簿 + 知识库）
2. 不迁移历史档案 Markdown（尤其 `07-L3以上客户档案/`）
3. 在新环境按白名单重建高质量档案

## 10. Clean Start 重建档案建议（高质量优先）

推荐使用模板：

- `/Users/clairaipartner/Codex/bussiness-master/configs/execution_batches/archive_rebuild_high_quality_template_v1.json`

推荐筛选门槛：

1. `信息扎实度 in {高, 中高}`
2. 关键字段完整：`公司产品与服务概述 / 商业模式概述 / admission_reason_summary / knowledge_asset_refs` 全非空
3. 每条主线优先均衡抽样，先小批次（如 20 家/主线）重建

重建验收：

1. 每页必须有来源定位与更新时间
2. 每页必须有 `remaining_gaps`
3. 不满足门槛对象不生成档案页，只入治理队列

## 11. 常见迁移遗漏

1. 只迁代码，不迁 `/潜客池/*.xlsx`
2. 迁了工作簿，但 registry 的 `source_paths` 仍是旧机器绝对路径
3. 迁了执行层三本表，但漏了 `知识资产注册表.xlsx` 与 `static-pool-raw-materials`
4. 多进程并发跑 write_back，未按锁机制串行执行
5. 走 Clean Start 却把旧 `07-L3以上客户档案/` 直接覆盖到新环境
