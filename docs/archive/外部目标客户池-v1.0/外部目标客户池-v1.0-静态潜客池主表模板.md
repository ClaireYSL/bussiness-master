# 外部目标客户池 v1.0 静态潜客池主表模板

## 1. 文档目的

本文件提供 `external_target_account_pool_v1` 的实际落表模板，供后续正式建池时直接复制使用。

本模板只服务 `静态潜客池`，不承载动态机会层的判断逻辑。

## 2. 推荐落表方式

建议使用电子表格或 Airtable / Notion 数据库，字段顺序按本文件执行。

推荐分为三层：

1. `核心必填列`
2. `增强列`
3. `动态预留列`

## 3. 主表字段顺序

### 3.1 核心必填列

| 字段名 | 中文名 | 说明 |
| --- | --- | --- |
| `account_canonical_name` | 目标账户归一主体 | 公司级主键，优先使用归一后的主体名称 |
| `brand_name` | 品牌名 | 市场常用品牌或业务名 |
| `group_name` | 集团名 | 归属集团或经营集团 |
| `primary_track` | 主线归属 | 零售消费 / 跨境电商 / 先进制造 |
| `industry_l1` | 一级行业 | 一级行业标签 |
| `industry_l2` | 二级行业 | 二级行业标签 |
| `business_model` | 业务模式 | 品牌零售、品牌出海、离散制造等 |
| `persona_tag` | 主画像标签 | 每条记录只填一个主画像 |
| `complexity_tag` | 经营复杂度标签 | 一句话概括复杂度来源 |
| `primary_jtbd` | 主 JTBD | 主要业务任务 |
| `current_business_problem` | 当前业务问题 | 一句话说明为什么值得打 |
| `case_type_match` | 案例类型匹配 | 对应案例类型 |
| `existing_customer_reference` | 存量客户样本 | 1 到 3 个已验证样本 |
| `solution_match` | 方案匹配 | 对应行业方案或打法 |
| `ai_bi_fit` | AI+BI 匹配度 | 高 / 中 / 低 |
| `static_priority` | 静态优先级 | A / B / C |
| `preferred_outreach_channel` | 优先触达方式 | 电话、邮件、活动邀约、伙伴转介绍等 |
| `opening_topic` | 推荐切入话题 | 前线开口的主要话题 |
| `reachout_reason_summary` | 触达理由摘要 | 1 到 2 句话 |
| `source_note` | 来源说明 | 官网、榜单、案例相邻品牌等 |

### 3.2 增强列

| 字段名 | 中文名 | 说明 |

### 3.3 动态预留列

| 字段名 | 中文名 | 说明 |
| --- | --- | --- |

## 6. 填写纪律

1. `persona_tag` 只填一个主画像，不允许同一单元格塞多个主画像。
2. `primary_jtbd` 必须写成任务，不写“数据乱”“报表慢”。
3. `reachout_reason_summary` 必须是前线能直接复述的话，不写抽象分析。
4. `dynamic_*` 字段允许为空，且不得影响 `static_priority`。
5. `existing_customer_reference` 优先使用已完成品牌/主体归一的客户名称。
