# 外部目标客户池 v1.0 范围与边界说明

## 1. 文档目的

本文件用于锁定 `外部目标客户池 v1.0` 的问题边界、对象边界和版本边界，避免后续执行中把不同层次的问题重新揉成一个模型。

v1.0 的核心不是“找到现在就会买的公司”，而是先建立一套 `面向 SDR / 市场 BD 的静态潜客统一总池`。

## 2. v1.0 要解决的问题

v1.0 需要回答：

- 哪些公司 `客观上` 符合观远的理想客户画像
- 这些公司为什么值得进入目标池
- 它们更像哪一类客户画像
- 观远已有哪类客户、案例、方案可以支撑前线触达
- SDR / 市场 BD 可以从什么话题切入

v1.0 不需要回答：

- 这些公司现在是否已经有明确项目
- 这些公司是否本季度一定值得 AE 重点投入
- 哪些公司已经处于商机成熟阶段
- 这些公司的联系人链路和 buying committee 是什么

## 3. 目标用户

- SDR
- 市场 BD

## 4. 核心使用场景

- 电话外呼
- 冷邮件
- 市场活动邀约
- 生态伙伴转介绍

## 5. v1.0 主交付物

v1.0 只交付 `静态潜客匹配层` 的作战资产：

1. 全国统一总池
2. 画像-潜客池-存量客户-案例映射规则
3. 静态评分与前线使用规则
4. 动态机会层的字段预留说明

说明：

- `优先触达池 / 视图` 不属于 v1.0 主交付物
- 后续正式的优先触达机制，应建立在 `静态潜客池 + 动态机会判断` 叠加之后

## 6. 术语定义

### 6.1 理想客户画像

一类可复用的目标客户类型，用于描述“什么样的公司值得被纳入观远的目标覆盖范围”。

粒度：

- 画像级

### 6.2 静态潜客池

依据画像规则筛出来的公司级目标名单，用于支持前线初始触达。

粒度：

- 公司级

### 6.3 动态机会池

在静态潜客池上叠加时间性信号、反馈信号和机会窗口信号后形成的优先经营对象池。

粒度：

- 公司级

说明：

- 不属于 v1.0 主交付
- 仅预留接口

### 6.4 触达建议层

把“为什么打 / 怎么打 / 拿什么案例打”转成前线可直接使用的解释层。

粒度：

- 公司级或画像级

## 7. v1.0 的设计原则

### 7.1 先分层，再定义

先区分：

- 理想客户画像
- 静态潜客池
- 动态机会池
- 触达建议层

再分别定义字段、规则和输出物。

### 7.2 先澄清对象，再设计字段

字段必须服务明确对象，不能为了“看起来完整”而堆叠。

### 7.3 只做静态潜客匹配，不混入动态机会判断

v1.0 的主判断对象是 `静态潜客匹配`，不是商机成熟度。

### 7.4 不让派生视图反过来主导建池

任何从静态潜客总池派生出来的工作视图，都不能：

- 反过来定义 v1.0 的核心目标
- 取代总池成为主交付物
- 被误用为正式优先触达池

### 7.5 先保证前线可用，再追求研究完整

每家公司只要求具备最小可触达信息集，不要求研究报告级深度。

## 8. v1.0 纳入范围

- 中国公司主体为主
- 公司级名单
- 全国统一总池
- 三条主线并行：
  - 零售消费
  - 跨境电商
  - 先进制造
- 中等验证深度
- 公司画像、JTBD 类型、观远匹配、触达建议、案例映射
- A/B/C 静态匹配优先级

## 9. v1.0 非范围

- 联系人级补全
- 全量组织架构核验
- 全量项目立项判断
- 动态商机评分主模型
- 深度区域归属和团队分配逻辑
- CRM 集成
- 自动化动态更新

## 10. v1.0 成功标准

当以下条件满足时，可视为 v1.0 成立：

1. 已形成一张 `全国统一总池`
2. 每家公司都能被解释为“为什么值得打”
3. A/B/C 被正确理解为 `静态匹配优先级`，而不是成交概率
4. SDR 可以直接挑选公司开始第一轮触达
5. 市场 BD 可以按主线 / 行业 / 画像筛选目标名单
6. 动态机会层未被错误并入静态潜客主模型

## 11. 与后续版本的边界

### v1.1 / v1.5 可扩展方向

- 动态机会判断机制
- 区域派生池
- 行业专池
- 部门级切入
- 联系人线索
- CRM / 市场反馈 / 销售反馈接入

### 边界约束

后续增强必须建立在 v1.0 的 `静态潜客统一总池` 之上，而不是回头修改 v1.0 的问题定义。
