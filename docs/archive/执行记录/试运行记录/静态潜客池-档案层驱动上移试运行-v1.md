# 静态潜客池-档案层驱动上移试运行 v1

## 摘要

本轮试运行以“先看档案完整度、再决定是否上移”为原则，选取 `绝味食品股份有限公司` 与 `厦门吉宏科技股份有限公司` 做一轮真实的档案层驱动上移。

本轮不是只改层级，而是同时完成：

1. 档案补证
2. evidence 增补
3. profile completeness 升级
4. `L4 -> L3` 正式上移
5. review queue 关闭
6. 共享层与浏览层同步

## 本轮对象

1. `绝味食品股份有限公司`
2. `厦门吉宏科技股份有限公司`

## 为什么选这两家

### 绝味食品股份有限公司

- 原状态：`L4`
- 原档案完整度：`minimum_ready`
- 画像：`retail_chain_fnb`
- 管理诉求画像：
  - `mgmt_frontline_action_loop`
  - `mgmt_hq_operating_visibility`

选择原因：

- 连锁网络和加盟经营属性已经较清楚
- 主线复用价值高，后续适合反复拿来解释零售网络与一线动作闭环
- 主要缺口已经从“是否成立”转向“颗粒度是否足够强”

### 厦门吉宏科技股份有限公司

- 原状态：`L4`
- 原档案完整度：`minimum_ready`
- 画像：`cbec_supply_chain_complex`
- 管理诉求画像：
  - `mgmt_profit_improvement`
  - `mgmt_inventory_supply_coordination`

选择原因：

- 跨境经营与包装印刷双轮驱动的业务结构已经较明确
- 跨境利润改善与供应链协同的解释链条已具雏形
- 当前缺口主要是更强的业务占比与平台结构颗粒度，而不是是否进入静态池

## 当前判断

这轮试运行证明：

- 档案层已经可以真正进入 `promote` 闭环
- 上移不再只是改 `L1-L5`，而是要同步更新：
  - 档案完整度
  - 证据
  - 话术资产
  - 队列状态
- 但当前仍主要适合“小批量、可解释”的上移，不适合一次性大批量无差别提升
