## 评估

### 本轮有效的地方

1. `候选发现来源` 增补后更清楚了
- 这轮不是“随手加公司”，而是能明确解释为什么这 5 家会进入候选。

2. `官方源优先` 可执行
- 至少对零售消费大品牌 / 大集团，这条路径是通的。

3. `静态背景补数` 已经能进入主表
- 不再只是入池一句话理由，已经能把公司快照做厚。

4. `主事实源 -> 共享层 -> Obsidian 浏览层` 可以联动
- 这轮没有停留在主表，而是同步进入阅读层和分享层。

### 本轮暴露的限制

1. 当前 `static-pool-expand` 仍更像“半自动入池 + 最小补数”
- 它已经不只是 onboarding；
- 但离“系统化发现大量新候选”还有距离。

2. 存量客户排除仍需更前置
- 本轮的珀莱雅、上海家化、百胜中国说明：
- 候选发现与官方补数跑通了，但老客排除没有足够前置。
- 以后必须在正式入池前先做更严格的“已知存量客户”排查。

3. 行业扫描能力仍偏人工驱动
- 本轮虽然使用了官方源 / 高可信源扫描；
- 但候选发现仍依赖人工挑选，而非稳定的半自动扫描清单。

4. 某些字段仍不适合强填
- 尤其是 `收入规模区间`、`利润状态概述`、`招聘代表岗位`；
- 在坚持官方源优先时，会天然出现留空。

---

## 结论

本轮说明：

- `static-pool-expand` 已经可以稳定扩出一批高静态可信的 `L5`；
- 但更适合“高质量小批量扩充”，而不是“无边界大放量”。

因此，当前对它的合理定位是：

- `默认用于小批量、高解释性、高静态可信度的 L5 扩展`

而不是：

- `全自动大规模找线索`

---

## 下一步建议

1. 继续按同样方式扩一批 `跨境电商` 或 `先进制造` `L5`，验证主线泛化能力；
2. 把 `官方源 / 高可信源行业扫描` 进一步收成半自动候选清单输入；
3. 对本轮最终保留新增的 `2` 家账户，后续优先补：
   - 收入规模区间
   - 多渠道 / 经销 / 门店颗粒度
   - 更直接的系统与经营协同证据
