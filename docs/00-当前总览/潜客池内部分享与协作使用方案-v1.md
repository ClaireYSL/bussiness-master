# 潜客池内部分享与协作使用方案 v1

## 1. 文档目的

本文件定义未来如何把静态潜客池内容分享给同事，并保持事实源稳定。

## 2. 分享原则

### 2.1 三层分享

1. `全量事实层`
2. `解释层`
3. `专题协作层`

### 2.2 唯一事实源

无论分享给谁，静态潜客池的唯一事实源仍然是 Excel。

Obsidian、导出文档、专题包都不是新的事实源。

### 2.3 当前默认团队共享主轴

未来默认不再尝试分享“整个 vault”或“整个共享版工作簿”。

团队共享主轴固定为：

1. `L3+ 客户档案页`
2. `L3+ 客户档案索引 Excel`
3. 必要时附专题包

## 2.4 分享状态

凡是进入团队包的对象，都应有分享状态：

- `未分享`
- `已分享`
- `已更新`

默认规则：

- 先生成本次团队包候选
- admin 确认后，标记为 `已分享`
- 后续默认不改
- 如果改了，标记为 `已更新`
- 下一次打包时明确区分：
  - `新增档案`
  - `已更新档案`

## 3. 全量事实层

### 承载形式

- Excel 共享版

### 适用对象

- SDR
- 市场 BD
- 销售负责人

### 建议内容

- 全量主表
- 高质量层
- `L4/L5` 扩展层
- 边界主体
- 主线汇总
- 画像汇总
- 背景快照字段区
- 主要知识资产与切入话术引用区

### 当前角色调整

`全量事实层` 继续保留为内部运营层，但不再作为团队默认交付主轴。

团队默认交付优先改为：

- `L3+ 客户档案索引 Excel`
- `L3+ 客户档案页`

## 4. 解释层

### 承载形式

- Obsidian note 导出
- Markdown / PDF

### 适用对象

- 管理层
- 行业团队
- 方案团队
- 策略同事

### 建议内容

- 主线 note
- 画像 note
- 重点公司 note
- 汇总与状态 note

### 当前角色调整

解释层中，团队默认优先消费：

- `L3+ 客户档案页`
- 少量重点公司 note
- 必要时专题包

不再默认把整个解释层一次性打包给团队。

## 5. 专题协作层

### 承载形式

- 专题包
- 会议材料
- 行业说明材料

### 适用对象

- 行业战役小组
- 活动项目组
- 跨部门协作对象
- 伙伴协作对象

### 固定结构

1. 专题范围
2. 为什么值得看
3. 对应主线
4. 业务形态画像
5. 经营诉求画像
6. 代表账户
7. 背景快照摘要
8. 样本客户与对应知识资产
9. 建议切入点 / 切入话术
10. 当前待验证重点

## 6. 重点公司分享策略

优先分享的重点公司类型：

1. `L1 + L2`
2. 边界主体
3. 用户点名关注公司
4. 画像代表账户

不建议优先分享：

- 普通 `L5`
- 仅作为放量候选的普通公司
- 仍缺乏基础判断的低稳定对象

## 7. 内部使用建议

### 如果同事想找公司

先看 `L3+ 客户档案索引 Excel`。

### 如果同事想理解为什么这家公司在池里

再看 `L3+ 客户档案页`；若该公司是重点样本，再看重点公司 note。

### 如果同事想准备会议或战役讨论

不要直接发全量池，应发专题包。

## 7.1 不再作为团队默认交付的内容

以下内容继续保留，但默认不再进入团队包：

- 全量浏览视图
- 全量状态页
- 执行与校验页
- rules 细节页
- evidence 明细
- archive
- `内部运营-静态潜客池-共享版.xlsx` 的全套内部 sheet

## 8. 当前边界说明

当前仍保留边界主体，不应作为稳定事实对外扩散：

- 深圳市万得福电子商务有限公司
- 厦门建发股份有限公司

## 9. 与 skill 的关系

未来与分享相关的动作，统一由 `static-pool-share` 承担。

它负责：

- 选择分享对象
- 选择分享层
- 选择分享形式
- 输出分享说明

它不负责：

- 扩池
- 清洗
- 上移
