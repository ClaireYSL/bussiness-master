# 知识原素材稳定根目录迁移建议-v1

## 1. 文档目的

本文件不执行迁移，只回答：

1. 当前知识原素材为什么需要迁出旧 workspace 路径
2. 哪些来源根需要优先迁移
3. 哪些内容不建议迁
4. 建议未来稳定根目录怎么设

这是一份迁移建议，不是迁移动作。

---

## 2. 当前问题

当前知识原素材虽然没有丢，但它们的物理根目录主要还压在旧 workspace 路径下：

1. `/Users/clairaipartner/.openclaw/workspace/geo-content/sources/L1客户案例`
2. `/Users/clairaipartner/.openclaw/workspace-main/dingtalk_docs/2026-03-28`

这带来三个风险：

1. 素材依赖旧工作区生存
2. repo 与知识源物理分离，长期不稳定
3. 未来若清理旧 workspace，知识学习链路会失去底层素材根

也就是说：

- 当前“素材没丢”不等于“路径稳定”
- 现在的问题不是可不可读，而是依赖位置太脆弱

## 4. 为什么需要迁稳定根目录

当前建议迁，不是因为现在坏了，而是因为：

1. 这两个来源根都属于旧 workspace 资产，不属于当前知识系统自己的长期素材根
2. 未来如果旧 workspace 重构、归档或清理，`raw_material_inventory.material_path_or_url` 会批量失效
3. 现在知识学习系统已经有正式账本和正式知识资产层，原素材也应该有稳定位置，而不是继续寄居在历史工作区

一句话：

- 当前原素材“可读”
- 但还不算“可长期维护”

---

## 5. 哪些应该优先迁

建议优先迁的是“仍可能被继续引用的真实原素材”，而不是全部文件一起搬。

优先级建议如下：

### 5.1 第一优先级

迁移：

1. `raw_material_inventory.material_status in {已转正式资产, 已入学习队列}`
2. `learning_queue.extraction_status in {queued, converted}`
3. `knowledge_assets.source_path_or_url` 当前仍回指旧 workspace 的条目

原因：

- 这些是当前系统已经在用，或极可能继续用的真实上游素材
- 它们最需要路径稳定

### 5.2 第二优先级

迁移：

- `raw_material_inventory.material_status = 待评估`

原因：

- 这些还没被吃，但仍可能未来继续学
- 是否迁可看空间和整理成本

### 5.3 最低优先级 / 可不迁

可不迁：

- `明确不学`
- `rejected`
- 流程入口占位项

原因：

- 它们不构成当前学习链路的必要输入
- 可以保留登记，不必优先搬运

---

## 6. 哪些内容不建议迁到素材根

以下内容不应混进新的稳定原素材根目录：

1. 潜客档案页
2. 重点公司 note
3. 专题包
4. 主表摘要导出
5. 模型生成说明
6. 阅读层 markdown 投影

原因很简单：

- 这些不是原素材
- 把它们混进去会再次污染学习源边界

## 8. 推荐迁移策略

如果后续决定真迁，建议按下面顺序做：

1. 先创建新稳定根目录
2. 先迁第一优先级素材
3. 批量改写 `raw_material_inventory.material_path_or_url`
4. 再校验：
   - `learning_queue.material_path_or_url`
   - `knowledge_assets.source_path_or_url`
5. 最后再决定要不要迁 `待评估`

不建议：

- 一上来全量搬 `189` 条
- 不改账本直接只搬文件
- 一边继续学习一边迁移

---

## 9. 当前建议结论

当前最合理的结论是：

1. 现在应该先承认旧路径仍在被依赖
2. 稳定化是必要的
3. 但本轮先做建议，不做文件迁移
4. 真执行时应先迁：
   - 已转正式资产
   - 已入学习队列
   - 当前 `queued / converted` 直接引用的素材

---

## 10. 下一步建议

如果继续推进，下一步最自然的是两选一：

1. 写“迁移执行清单 v1”
   - 只列出第一优先级需要迁的文件清单

2. 真正开始迁移
   - 创建稳定根目录
   - 小批量搬文件
   - 回写账本路径

当前更稳的是先做第 1 步。
