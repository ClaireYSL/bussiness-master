# BusinessMaster 知识资产来源边界与潜客观察隔离原则 v1

## 1. 结论

潜客池产出不能直接沉淀为正式知识资产。

M21R/M22R 证明的是：某家公司与当前 ICP/画像匹配，并且核心信息可追溯。它不能证明这家公司是我们的真实客户、真实案例、画像正例或解决方案样板。

## 2. 为什么要隔离

1. 潜客是外部候选，不是已服务客户。
2. 官方来源只能证明公司事实，不能证明我们对该类公司的解决方案已被验证。
3. 批次结果来自当前规则，不能反过来训练或覆盖规则本身。
4. LLM 可以整理观察，但不能把观察变成事实源。

## 3. 允许进入正式知识资产的来源

1. 已服务客户案例。
2. 内部解决方案材料。
3. 已验证的方法论、话术和场景包。
4. 行业研究、年报、公告、IR、监管披露等权威材料。
5. 经人工评审通过的映射事实或标尺样本。

## 4. 潜客批次只能产出什么

1. `candidate_observation`：候选观察。
2. `persona_boundary_question`：画像边界问题。
3. `source_gap`：缺什么真实素材。
4. `rule_calibration_proposal`：待评审规则建议。
5. `trusted_prospect_card`：可信潜客摘要卡。

这些产物可以帮助我们发现知识库哪里薄，但不能直接写入正式知识资产。

## 5. M24R 新口径

M24R 不再叫“从潜客沉淀知识资产”。

M24R 的目标改为：知识资产来源治理与画像规则校准。

产出应包括：

1. 来源白名单和禁用来源清单。
2. 潜客观察包。
3. 画像规则校准建议。
4. learning_queue 补源任务。
5. 不写入正式知识资产的证明记录。

## 6. 正确链路

```text
潜客观察
-> learning_queue 补源任务
-> 找到真实客户案例 / 解决方案 / 行业权威材料
-> 人工评审
-> 正式 knowledge_assets 或 persona_registry 更新
```

任何跳过真实素材验证的链路都应被 gate 拦截。
