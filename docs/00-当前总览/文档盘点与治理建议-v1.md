# 文档盘点与治理建议-v1

## 1. 这份文档解决什么问题

当前工作区的文档问题，已经不是“缺文档”，而是“文档过多、层级混杂、历史执行残留过重”。

如果现在直接去全局修旧路径引用，收益不高，原因是：

1. 很多文档已经不是当前有效入口
2. 大量一次性执行文档不值得继续维护
3. 不先确定哪些文档仍然活着，就会把历史噪音继续当成现行制度维护

因此当前更合理的顺序应改为：

1. 先盘点
2. 先分层
3. 先定保留/合并/归档口径
4. 最后只清理“活文档”的旧引用

## 3. 建议采用的文档分层

后续建议把整个 repo 文档固定理解为 5 层：

### 3.1 入口层

回答：

- 当前项目现在到底以什么为主线
- 新人应该先看什么
- 当前默认事实源、知识源、执行源在哪里

建议只放在：

- `docs/README-静态潜客池.md`
- `docs/00-当前总览/`

### 3.2 制度层

回答：

- 当前有效规则是什么
- 什么能做，什么不能做
- 入池、上移、冻结、学习接入如何执行

建议只放在：

- `docs/01-机制与规则/`

### 3.3 结构层

回答：

- 工作簿字段和注册表结构是什么
- 状态、枚举、表关系是什么

建议只放在：

- `docs/02-注册表与结构/`

### 3.4 执行索引层

回答：

- 当前还有哪些执行专项在跑
- 哪些批次记录值得追
- 哪些专项只是历史结果

建议保留在：

- `docs/03-执行与校验/`

但这里应只保留：

- 当前总索引
- 当前阶段仍会复用的少量专题
- 少量跨批次汇总文档

不应继续放大量单批次执行残留。

### 3.5 研究/归档层

回答：

- 方法论如何演化
- 历史方案长什么样
- 旧阶段的过程记录是什么

建议放在：

- `docs/04-研究与方法/`
- `docs/archive/`

## 8. 当前结论

一句话总结：

- 当前 repo 最该治理的不是规则层，也不是 archive
- 而是现行目录里仍混着大量历史执行残留

因此最优先动作应是：

- 先把文档分成“现行入口 / 现行规则 / 现行结构 / 执行索引 / 历史归档”
- 再把 `03-执行与校验` 中的一次性批次文档整体降级
- 最后才清理活文档中的旧引用

如果后续继续执行，本建议的第一优先级应是：

- 产出一份 `03-执行与校验` 的正式归档迁移清单
